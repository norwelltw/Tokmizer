# Replaying the compression benchmark

`packages/plugin/bench/` replays saved command outputs through the built Claude Code hooks of the plugin and reports how many tokens reach the agent. It runs offline, needs no account and does not touch your real Tokmizer or Claude Code folders.

## Run it

From the repository root, on macOS or Linux, with Node.js 20.11 or later:

```sh
npm ci
npm --workspace packages/plugin run build
node packages/plugin/bench/run.mjs
```

Options:

- `--verbose` prints one line per case: raw tokens, tokens in the default mode, tokens with commands rewritten.
- `--out result.json` writes the full report, with every case.
- `--only id1,id2` replays only the listed cases (ids from `bench/corpus.json`).
- `--corpus path/to/corpus.json` replays another corpus in the same format; its `file` entries are read relative to that file. Use it for outputs that must stay out of the repository.

A full run of the 102 cases takes about 40 seconds.

## What it does

For each case, the script creates a temporary folder with its own home, sets `TOKMIZER_NETWORK=0` and `TOKMIZER_AUTO_UPDATE=0`, and disables the background process. A stand-in for the command (for example `ctest` or `./vendor/bin/pest`) prints the saved output and exits with the recorded exit code. Each case is then measured in two modes, the same two modes as the published results:

- **Default mode**: Claude Code's default permission mode. The after-command hook (`dist/hooks-host/post-tool-use.js`) runs only when the command succeeds. A failing command reaches the agent unchanged and is counted raw.
- **Commands rewritten**: `bypassPermissions`. The before-command hook (`dist/hooks-host/pre-tool-use.js`) rewrites the command, the rewritten command runs through `tkr-exec` against the stand-in, and the after-command hook runs on success. A command the hook does not rewrite runs as typed; the report lists those cases under `notRewritten`.

When an output is longer than 30,000 characters, the script reproduces how Claude Code hands it to the after-command hook: the first 30,000 characters in `stdout`, the full text in a `tool-results` file, and its size. This mirrors what the hook expects; it was not checked against a live Claude Code session.

## Slices

- `all`: every case, full outputs.
- `claude-code-30k-cap`: every case, with the raw output and the output seen by the agent both cut at 30,000 characters, the limit Claude Code displays.
- `outputs-under-30k-chars`: only the cases whose raw output is under 30,000 characters.

Each slice gives the raw token total and the percentage of tokens removed in each mode.

## Token count

If `js-tiktoken` can be resolved from `packages/plugin`, tokens are counted with `o200k_base`, as in the published results. Otherwise `@anthropic-ai/tokenizer` is tried. Without either, the script uses characters divided by 4 and says so in its output. The repository does not install a tokenizer; to get `o200k_base`, install `js-tiktoken` yourself before running the script.

## Corpus

`bench/corpus.json` lists 102 cases:

- 99 outputs from the plugin's own test fixtures in `packages/plugin/src/__tests__/fixtures/` (`v4`, `rtk10`, `test-failures`, `fidelity/failures` and five large `audit` outputs: `cargo`, `gcloud`, `next`, `pytest`, `terraform`). These files ship with the public source. Some are synthesized, some are real captures with paths anonymized, and some come from rtk's own Apache-2.0 fixtures.
- 3 large synthetic outputs generated by `bench/synthetic.mjs` with a fixed seed: `git log --stat`, `find .` and `grep -rn`.

Captures of private repositories are not part of the corpus.

## Relation to the published results

The results published on 2026-10-17 (`/benchmarks/2026-10-17.json`, 68 cases, Tokmizer 0.9.60 against rtk 1.0.1) were measured on a corpus that is not in this repository: part of it replayed outputs of private repositories. This harness does not reproduce those figures. It measures Tokmizer only, on a different and public corpus, and does not compare with rtk or measure latency.

Results of this harness on 2026-10-18, Tokmizer 0.9.65, macOS on Apple Silicon, Node.js 24:

| Slice | Cases | Raw tokens | Default mode | Commands rewritten |
| :-- | --: | --: | --: | --: |
| all, `o200k_base` | 102 | 476,379 | 75.6% | 87.3% |
| 30,000-character cap, `o200k_base` | 102 | 151,510 | 48.9% | 66.9% |
| outputs under 30,000 characters, `o200k_base` | 94 | 69,172 | 14.0% | 58.2% |
| all, characters ÷ 4 | 102 | 356,028 | 74.7% | 87.8% |
| 30,000-character cap, characters ÷ 4 | 102 | 117,134 | 46.8% | 67.9% |
| outputs under 30,000 characters, characters ÷ 4 | 94 | 57,134 | 14.9% | 58.2% |

`python -m pytest -q` was not rewritten by the hook in this run and counts raw in both modes. Two consecutive runs gave identical numbers.

## Limits

- Token counts of command output, not tokens per session, cost or task success.
- No live agent session: the hooks are called directly with Claude Code's payload format.
- Outputs go through `stdout` unless the case says `stderr`; real commands often mix both.
- macOS and Linux only: the stand-in commands are shell scripts.
- `packages/plugin/scripts/replay-bench.mjs` is a different tool: it replays your own Claude Code transcripts from `~/.claude/projects` and is not used here.
